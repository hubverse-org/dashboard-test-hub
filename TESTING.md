# Dashboard Test Hub

This repository is a fork of [example-complex-forecast-hub](https://github.com/hubverse-org/example-complex-forecast-hub), repurposed as a dedicated test fixture for the hubverse dashboard pipeline.

## Purpose

The dashboard pipeline spans multiple repos (predtimechart, hubPredEvalsData, predevals, site-builder, control-room) but had no controlled environment for:

- Testing tool changes against a known-good hub and dashboard config
- Testing new config schema versions against realistic data
- Staging changes end-to-end before releasing
- Running CI smoke tests for PRs to component repos

This test hub, paired with its companion [dashboard-test-hub-dashboard](https://github.com/hubverse-org/dashboard-test-hub-dashboard), fills that gap.

## What's in this hub

Forked from `example-complex-forecast-hub`, this hub contains:

- **3 models**: Flusight-baseline, MOBS-GLEAM_FLUH, PSI-DICE
- **4 reference dates**: 2022-10-22, 2022-11-19, 2022-12-17, 2023-01-14
- **52 locations**: US national + 50 states + DC + Puerto Rico
- **4 targets** across 3 `model_tasks` blocks:
  - PMF: `wk flu hosp rate category`
  - CDF: `wk flu hosp rate`
  - quantile / sample / mean / median (multi-target block): `wk inc flu hosp` **and** `wk inc flu death`

The data volume is intentionally small (~24 MB) to keep pipeline runs fast.

### Multi-target-per-block fixture

The quantile block carries **two** targets sharing the same `task_ids` and `output_type`, mirroring the structural pattern in CDC's COVID-19 Forecast Hub ([`tasks.json`](https://github.com/CDCgov/covid19-forecast-hub/blob/main/hub-config/tasks.json)) that surfaced [hubverse-org/hub-dashboard-predtimechart#88](https://github.com/hubverse-org/hub-dashboard-predtimechart/issues/88) — "Forecasts don't build if there are multiple targets within a single task block".

The sample block declares `compound_taskid_set: [reference_date, location, target]` — including `target` means each (target, location, reference_date) gets an independent sample population (joint across horizons within it). To satisfy this configured compound, the two targets use **disjoint sample-id ranges**: `wk inc flu hosp` samples occupy ids 1..5300, `wk inc flu death` samples occupy 1000001..1005300 (offset applied by `internal-data-raw/add_second_target.R`). Without the offset, `hubValidations` infers the actual compound as the *coarser* `[reference_date, location]` and warns.

This fixture exercises:

- multi-target-per-block parsing in `hub-predtimechart`, `hubPredEvalsData`, and `predevals` (regression fixture for predtimechart#88)
- `compound_taskid_set` validation including `target` ([hubverse-org/hubValidations#332](https://github.com/hubverse-org/hubValidations/issues/332))
- end-to-end sample handling in dashboard tools and the upcoming Sprint C sample-based scoring work ([eval-metrics-expansion](https://github.com/reichlab/decisions/blob/main/project-posters/eval-metrics-expansion/eval-metrics-expansion.md#mini-sprint-c--sample-based-scoring-with-compound_taskid_set))

The fixture is regenerated by re-running the scripts in `internal-data-raw/` — see that README for the full pipeline (including the upstream-merge recovery flow).

## How to use

### Stable baseline testing

The `main` branch provides a known-good baseline. Run the dashboard pipeline against it to verify tool changes don't break anything.

### Branch-based development

For changes that affect hub structure (e.g., new output types, modified round structure):

1. Create a branch on this repo with the modified hub config and data
2. Create a matching branch on the dashboard repo with updated config
3. Run the pipeline against both branches to verify end-to-end

### Regenerating data

The `internal-data-raw/` directory contains R scripts to regenerate model output and target data from original sources. See `internal-data-raw/README.md` for instructions.

## Syncing with upstream

This repo maintains a fork relationship with `example-complex-forecast-hub`. To pull upstream changes (e.g., hub schema updates):

```bash
git fetch upstream
git merge upstream/main
```
